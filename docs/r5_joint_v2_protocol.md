# R5 joint-v2 protocol

Joint scientific authority is one complete generation represented by identical `state_authority/AUTHORITY` records in T1 and T2. No mode bits, HEAD, predecessor, genesis, rollback or tombstone mechanism participates in authority. T3 remains outside this protocol.

## Inventory and record

The ASCII/LF record starts with `#RTB-JOINT-AUTHORITY<TAB>2`. Ordered metadata declares state, boundary (hex barcode, hex round, generation, full_round), hex context, byte-sorted barcode roster and consecutive configured target ordinals. Sorted group records bind kind, hex key, rule and count. Entries sort by decoded full relative path, encode paths as lowercase even-length hex, and declare A (absent), D (directory) or F (size and SHA-256). The final `#END` contains group count, entry count and SHA-256 of all preceding bytes. A marker binds SHA-256 of the entire record including this footer.

Governed groups are the existing F01 closed inventory; exact Consensus/.cache tree including hidden entries and empty directories; ownership and canonical consolidated IDs; each configured BLAST CACHE/EVIDENCE/MEMTAX triple; five-file parser units; three-file read-fate units; both previous-round grace families; and both rolling-SUP names. Absence is distinct from an empty regular file or empty directory. Unit groups must be all-present or all-absent, with the current completed parser/read-fate units present. BLAST absence also requires no current governed demand at capture. Read-only existing validators check parser contracts and the R4 projection.

Reject unsafe paths/components/ancestors, symlinks and special nodes, duplicates, noncanonical ordering or integers, partial groups, unexpected governed content, wrong counts/digests and trailing bytes. Cache child names are ordinary encoded data except the protected round-lock namespace. Bounded parsing and sorted spill runs avoid allocating according to untrusted counts.

## Publication and restore

A fresh authenticated full-round backup pin covers normalization, candidate construction and complete T1 capture. Candidate metadata is finalized first. Hold the existing root locks in T1 then T2 order, retaining descriptors across supervised descendants. Install identical canonical `.f03-transaction` markers before invalidating either authority; invalidate both before any payload change. Preserve the existing all-roots-first order and root-ledger callsite within that fenced interval.

Finish the round only after complete T1 capture. Subsequent verification, T2 replication and sealing consume retained candidate/T1 material only. Reverify each payload, install identical seals, and verify both sealed payloads while both markers remain. Remove only matching owned markers after joint proof. A completed retry may use its exact authenticated retained transaction, never live recapture, normalization or newer generation material.

Restore is read-only until admission succeeds. It refuses live pending evidence, canonical or temporary transaction evidence, `.f03-txn`, reserved residue, unequal roots, damaged present peers and completed v1 snapshots. It never repairs publication state. Choose one admitted generation, filter governed transport aliases from ordinary overlays, then install governed state last. Never union caches.

Only the 14 approved chart TSV leaves, proven PDF families with known generated identities, and checked existing layout/alias relationships receive presentation treatment. Their ancestors remain subject to safety checks. Unknown async destinations and aliases refuse; scientific targets do not become presentation because an alias names them.

## RF-PIN and authoritative order

A fresh `/bin/bash` worker owns its round pin and history-lock metadata under its real PID. The parent records `$!`, validates the native-start/pin handshake, waits synchronously and validates the completion receipt. Native process start supplements the existing pin representation; it does not change stale-owner policy. Release history lock, validate and remove the exact whole pending witness, write the private success receipt, exit, then retire the dead worker pin.

Both order checks and every joint repair supply `--round-index-file PATH`. Explicit empty paths refuse. Only the headerless mapping controls order; indices match `[1-9][0-9]{0,8}`. Duplicate names/indices, malformed rows, unmapped identities, missing boundaries or retained prefixes and feeder-filter combinations refuse. Production identities ending `_0` remain valid. The optional CLI argument is suppressed from legacy help; absent-option behavior remains unchanged.

The pending-v4 witness binds state, authenticated generation, `full_round` scope, replay context (ordered targets, target taxa and assignment level), terminal identity and every ordered obligation. Each obligation commits biological barcode, through-round, global index and the SHA-256 of the canonical ordered prefix. Every authoritative round through the terminal has one stable round-JSON projection digest and exactly eight retained-input records in this order: read-info, on-target, demult, pretax BLAST OTU, unassigned list, annotated OTU evidence, noadapter OTU and round-local index. The stable projection excludes `read_fate` and `warnings`; duplicate JSON keys refuse, and JSON types are preserved. Paths are derived from the mapped round and its own barcode, never supplied by the witness.

The first four per-round inputs must be safe regular files before witness creation or any mutation; present-empty is valid and differs from absence. Their records are `F<TAB>size<TAB>sha256`. The remaining four record either `A` for absence or `F` with exact size and digest. A recorded absence must remain absent; a recorded file must retain its exact bytes. The ASCII/LF witness uses canonical line order and decimals and one final `#END` digest; malformed and legacy/v3 witnesses refuse. B1→B2 adoption verifies context and all old round/input records before writing, copies old records byte-for-byte and appends only newly authoritative rounds. Repeated barcodes share their round records. Verify the durable records before and after every helper call, during final verification, immediately before history-lock release and immediately before witness removal. Completed retries and dorado-only never normalize or clear pending evidence.

The worker derives first-seen rows and sidecar expectations from retained producer bytes before invoking repair. Private shadow inputs feed the unchanged round/run report builders and R4 resolver. After each call it compares the complete bounded read-fate values, immutable round fields, warnings, unassigned IDs, run-report completion and reached R4 outputs; it verifies retained input identities and hashes, historical receipts, latest physical outputs and the complete ordered terminal history again before commit. Wall-clock run freshness fields receive explicit clock/value checks. Hashing the helper's own output is not the scientific oracle.

Recovery requires restoring exact retained F bytes or the recorded A absence, owner-authorized whole-namespace replacement, or a fresh namespace replay. Before first capture, an EQUIV input's lost nonempty bytes cannot be inferred from current absence; restore from authenticated workflow evidence. Fabricating an empty file to satisfy the mandatory presence rule is forbidden. The worker never creates, deletes or repairs retained producer inputs.
